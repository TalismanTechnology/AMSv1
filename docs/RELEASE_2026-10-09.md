## Deploy checklist (in order)

1. **Before deploying**, in the Supabase SQL editor (production), run in order:
   1. `supabase/migrations/031_flagged_chat_access.sql`. Without it, the
      chat route's message inserts fail (missing `unanswered` column) and the
      admin feedback page breaks.
   2. `supabase/migrations/032_email_ingestion_review.sql`. Without it, mail
      to schools with no allowlist fails closed (webhook 500).
   3. `supabase/migrations/033_account_deletion_fks.sql`. App-side deletion
      works without it, but it is the DB backstop.
   4. `supabase/migrations/035_ai_processing_consent.sql`. **Required.**
      Without it every chat request is rejected (profile query fails, then
      the consent gate returns 403).
2. **Before #10's behavior goes live:** in Admin → Settings → Email Ingestion
   for **Collegiate** (and any other live school), add the allowed sender
   domains. Otherwise all of their inbound email starts waiting in
   "Recent emails" for manual approval.
3. Merge this release PR into `main` (Vercel deploys). Then close
   #8–#13, #15, #16 as merged via this PR. #14 stays open.
4. **Env vars / secrets (can come later, nothing breaks without them):**
   - `APPLE_TEAM_ID` in Vercel, once the Apple Developer account exists
     (AASA serves a `TEAMID` placeholder until then).
   - GitHub Actions secrets for the manual TestFlight workflow:
     `APPLE_TEAM_ID`, `ASC_KEY_ID`, `ASC_ISSUER_ID`, `ASC_KEY_P8_BASE64`.
   - APNs (`APNS_KEY_ID`, `APNS_TEAM_ID`, `APNS_PRIVATE_KEY`, `APNS_BUNDLE_ID`)
     if not already set.
   - No new env vars are required for the web deploy itself.
5. **Expect after deploy:**
   - **Every existing user sees the AI consent dialog once**, before their
     next chat question (staff previewing chat too). Declining sends nothing.
   - **Top questions** on the admin dashboard only show a question once
     **3 or more different parents** asked it, so the list may look emptier.
   - School staff can now read only flagged exchanges (unanswered or
     thumbs-down), not full parent conversations.
   - The UI font changes slightly (Inter instead of Helvetica Neue).
6. Legal text on `/privacy` and `/terms` is still a **draft**. Get it
   reviewed before pointing App Store / Play listings or a school DPA at it.
7. No new iOS build is needed for the web changes. #15's native changes
   need a TestFlight build once Apple credentials exist.
